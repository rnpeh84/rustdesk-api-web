# Portainer 스타일 로컬 시안

2026-10-07 작업. 사용자 요청에 따라 전체 관리자 화면의 색상·간격·공통 컴포넌트 스타일을 변경했다. 기능, 메뉴 구조, API와 인증 계약은 유지한다. 커밋·push·운영 배포 및 상위 `resources/admin/` 교체는 수행하지 않았다.

## 두 번째 시안의 기준

첫 시안은 색상과 간격 위주여서 Portainer의 컴포넌트 구조와 차이가 컸다. 두 번째 시안은 사용자가 열어둔 실제 Portainer의 Dashboard와 Containers 화면을 읽기 전용으로 확인한 뒤 다시 구성했다. 참조 화면은 다크 테마이며, 라이트 테마는 같은 구조에 대응하는 밝은 색상으로 구성했다.

색상 기준은 사이드바 `#2e2f33`, 다크 배경 `#111111`, 다크 패널 `#212121`, 다크 표 헤더 `#383838`, 라이트 배경 `#f5f5f5`, 활성 링크 `#087ea4`다.

```text
사이드바 280px | 경로·계정 헤더 64px
              | 열린 페이지 탭
              | 간결한 페이지 제목 18px
              | 가로형 지표 카드 / 필터·표 패널
              | 표·페이지 이동 또는 상세 패널
```

## 디자인 범위

- 라이트·다크 모두 짙은 회색 사이드바와 회색 활성 메뉴·그룹을 사용한다.
- 상단에 경로·계정을 배치하고 열린 페이지 탭과 작은 제목을 분리한다. 기존 중복 경로 표시는 숨긴다.
- 패널 헤더의 원형 아이콘, 데스크톱에서 한 줄 네 개의 약 65px 높이 대시보드 지표 카드를 사용한다. 패널 종류에 맞는 아이콘을 표시한다.
- 표를 패널 가장자리까지 확장하고 세로 구분선을 줄인다. 회색 표 헤더, 약 50px 기본 행, 10px 패널·6px 버튼 모서리를 사용한다.
- 일반 버튼·입력은 30px 높이로 정리하고 다크 테마의 주요 버튼은 밝은 바탕으로 표시한다.
- 폼·팝업·드롭다운·페이지 이동·상태 안내와 대시보드 패널의 공통 색상을 통일한다.
- 기존 아이콘 작업과 두 단계 삭제 확인, 오프라인 연결 비활성화는 유지한다.
- 터미널·파일 작업 영역은 기존 어두운 작업 화면을 유지한다.
- 한국어 글꼴 체계와 기존 테마 전환을 사용하며 의존성을 추가하지 않았다.

## 변경 및 되돌리기

시안 스타일은 `src/styles/portainer.scss`에 분리했다. `src/main.js`에서 이 파일을 가져오고 `html.portainer-ui` 클래스를 설정한다.

- 시안: `http://127.0.0.1:15176/#/my/peer`
- 기존 디자인 비교: `http://127.0.0.1:15176/?ui=classic#/my/peer`
- 시안으로 돌아오기: URL에서 `ui=classic`을 제거하고 새로고침한다.
- 시안을 비활성화하려면 `src/main.js`의 `portainer-ui` 클래스 설정을 제거한다. 추가 경로와 패널 아이콘도 기본적으로 숨겨져 기존 배치로 돌아간다.
- `ui=classic`은 Portainer 스타일과 자동 필터 적용을 비활성화한다. 공통 아이콘 작업과 두 단계 삭제 확인은 별도 UI 보완이므로 유지된다. 소스 전체 되돌리기는 현재 diff에서 시안과 공통 UI 보완을 구분해 수행하며, 관련 없는 사용자 변경은 되돌리지 않는다.

기본 테마 설정은 기존 전환 버튼으로 변경한다. `ui=classic`은 테마·데이터·기능을 변경하지 않고 스타일 계층만 비활성화한다.

## 로컬 검증 환경

임시 DB와 모의 장치를 사용하는 기존 `TestBrowserTerminalIntegration` 검증 서버를 `127.0.0.1:15175`에 실행했다. `runtime/sharing-ui/portainer-preview.mjs`는 빌드된 `dist/`를 `127.0.0.1:15176`에서 제공하는 로컬 전용 프록시다. 운영 서버로 요청하지 않는다.

관리자 전체 메뉴 검증을 위해 프록시에서 관리자 역할·메뉴와 사용자·그룹 샘플을 제공한다. 지원되지 않는 조회는 빈 데이터로 표시한다. 따라서 운영 수치, 계정 생성, 권한 검증의 결과로 해석하면 안 된다. 장치·주소록·공유·모의 터미널은 임시 검증 서버로 연결된다. 재실행한 검증 서버는 기존 수동 미리보기의 8시간 종료 제한을 사용한다.

프런트엔드 변경 후 `npm run build`를 실행하면 해당 로컬 서버에서 새로고침해 결과를 볼 수 있다. 로컬 프록시는 루트 작업공간에서 `node runtime/sharing-ui/portainer-preview.mjs`로 실행한다. 기존 임시 검증 서버가 먼저 실행되어 있어야 한다.

모든 페이지의 모든 업무 동작을 재검증한 것은 아니다. 공통 스타일 적용과 대표 화면의 로컬 시각·상호작용 검증 범위이다.

## 검색 도구 모음과 공통 작업 보완

- 23개 목록 화면의 기존 필터 영역을 `QueryToolbar`로 통일했다. Portainer 시안은 필터 실행 버튼을 숨기고 실제 검색 조건만 350ms 후 자동 적용한다. Enter는 즉시 적용하며 페이지 이동은 기존 조회 흐름을 유지한다. 한글 입력 조합 중에는 조회하지 않고, 화면 이탈 시 예약된 조회를 취소한다.
- 검색 필드 이름은 입력칸 안에 표시하며 접근성 이름도 유지한다. 선택 조건은 라벨을 유지한다. 검색 조건이 없어도 작업 버튼이 있으면 공통 패널과 여백을 유지하며, 검색 조건과 작업이 모두 없는 영역만 숨긴다.
- 상단의 추가·초기화·일괄 편집·가져오기·내보내기는 아이콘과 짧은 작업 이름을 함께 표시한다. 추가 등 주요 작업은 채운 버튼, 나머지는 중립색 테두리 버튼으로 구분한다. 표 안의 작업과 공유 현황 이동은 아이콘을 유지한다. 모든 아이콘에 툴팁과 접근성 이름을 제공하고 모바일은 입력칸을 한 열로 배치한다.
- 주소록 안내 문구를 표 셀과 같은 16px 안쪽 여백에 정렬했다. 표 아래의 공유 관리 텍스트 링크는 상단의 공유 현황 이동 아이콘으로 옮겼다.
- 장치 관리의 사용자·그룹은 한 줄로 표시한다. 대시보드의 불필요한 설치·서버 설명은 제거하고 OS별 x64/ARM64 복사 작업을 한 줄씩 정리했다. 설정 저장 방식과 재설치 선택 사항은 유지한다.
- 주소록·장치·사용자·그룹·태그·기록·빌드 설정의 일반 삭제 및 공유·토큰·로그인 세션 해제는 공통 확인 버튼을 사용한다. 첫 클릭은 같은 위치에서 V로 바뀌고 두 번째 클릭에서 실행한다. 초점 이탈·Esc·5초 시간 초과·대상 변경 시 취소하며 요청 처리 중에는 실행을 잠근다. 기존 지침은 루트와 웹 `AGENTS.md`에 이미 명시되어 있다.
- 실제 원격 파일 삭제, 미저장 내용 버리기, 비밀번호·2FA·계정 연결 변경 및 정책·배포·빌드 제어의 추가 확인은 해당 작업의 기존 보호 흐름을 유지한다.
- 확인 상태·취소·중복 차단·실패 복구와 검색 예약·Enter·화면 이탈 테스트 9개가 통과했다. 실제 브라우저에서 주소록 삭제의 첫 클릭/V·Esc·초점 이탈·시간 초과를 확인했으며 실제 데이터 삭제는 실행하지 않았다.
- 브라우저에서 장치 ID 입력 후 2건에서 1건으로 자동 조회되고 초기화 후 2건으로 돌아오는 것, 주소록 선택 후 해당 책 항목만 표시되는 것을 확인했다. 데스크톱의 한 줄 검색 및 소유자 표시, 390×844 모바일·768×1024 태블릿의 문서 가로 넘침 없음, 라이트·다크를 확인했다.
- 설치·서버 영역은 모의 환경의 빈 서버 설정으로 확인했다. 복사·QR 버튼의 비활성화는 정상이며 실제 설치 명령 실행이나 운영 연결 검증은 하지 않았다. 모든 페이지의 모든 CRUD API를 재검증한 결과로 해석하지 않는다.
- 변경은 로컬 소스와 `dist/`에만 반영한다. 루트 운영 웹 리소스 복사, 커밋·push·배포·PC 종료는 수행하지 않는다.
- 최종 빌드 통과(29.95초). 기존 500kB 초과 청크 안내는 유지된다. 모바일 설치 OS 아이콘은 18px 폭을 유지하며, 최신 `ui=classic`의 필터 버튼 복원도 확인했다. 사용자 로컬 탭을 최신 빌드로 갱신하고 검증용 탭·화면 크기 변경을 정리했다.

## 상단 작업 버튼의 이름과 정렬 보완

- 사용자가 제공한 실제 Portainer 컨테이너 목록을 읽기 전용으로 확인했다. 상단 `Add container`는 아이콘과 글자를 함께 사용하며 다크 테마는 밝은 중립색 채움, 표 내부 작업은 작은 아이콘이었다. 확인한 주요 버튼은 12px 글자와 8px 모서리를 사용했다.
- 공통 `QueryToolbar`의 숨겨진 작업 이름을 다시 표시했다. 입력·선택·버튼 높이를 모두 32px로 맞추고 검색칸의 최소 폭을 줄여 주소록 선택·세 검색칸·두 작업을 데스크톱에서 한 줄로 정렬했다. 다크 테마의 주요 버튼은 참고 페이지와 같은 `#f7f6f3` 배경과 `#2e2f33` 글자, 라이트 테마는 기존 시안의 주요 색을 사용한다.
- 정책 관리 패널에서 페이지 제목을 반복하던 `PolicyManage` 문구만 제거했다. 설명과 정책 추가·편집·배포 기능은 유지한다.
- 로컬 브라우저에서 주소록 추가 팝업 열기·취소, 390px 모바일과 768px 태블릿의 문서 가로 넘침 없음, 장치 그룹의 동일한 추가 버튼과 키보드 초점 표시를 확인했다. 실제 추가·삭제·정책 배포는 실행하지 않았다.
- 변경은 로컬 소스와 미리보기 빌드 범위다. 커밋·push·운영 배포·PC 종료는 수행하지 않는다.
- 최종 빌드 통과(39.79초), 변경 파일의 diff 검사 통과. 브라우저에서 정책 패널 안의 중복 제목이 없음을 확인하고 사용자 로컬 탭을 최신 빌드로 갱신했다. 검증 탭을 닫고 임시 화면 크기를 복원했다. 기존 500kB 초과 청크 안내는 유지된다.

## 작업 패널 유지와 주소록 ID 정렬

- 상단 작업 패널은 검색 조건 유무와 관계없이 12px 세로·16px 가로 여백과 패널 배경·테두리를 유지한다. 로그인 로그 등 8곳의 일괄 삭제는 아이콘과 작업 이름을 함께 표시하고 위험 동작의 색상을 유지한다. 표 안의 개별 삭제는 기존 아이콘을 유지한다.
- 같은 위치의 두 단계 확인은 첫 클릭에 아이콘만 V로 바뀌며 작업 이름을 유지한다. 실제 브라우저에서 일괄 삭제 버튼의 좌표·너비가 확인 전후 같고 Esc로 취소되는 것을 확인했다. 실제 삭제 요청은 실행하지 않았다.
- 사용자·관리자 주소록 ID 머리글과 본문을 왼쪽 정렬하고 16px 안쪽 여백을 적용했다. OS 아이콘·ID·복사 버튼은 8px 간격의 한 줄로 표시한다.
- 주소록 상단의 추가·태그 일괄 편집을 실측했다. 높이 32px, 글자 12px, 아이콘 14px와 세로 좌표가 동일하며 너비는 작업 이름에 따라 약 63px·114px이다.
- 최종 로컬 빌드 통과(9.12초), 확인 상태·검색 예약 테스트 9개와 변경 파일 diff 검사 통과. 라이트·다크 작업 패널, 390px 모바일·768px 태블릿의 주소록과 문서 가로 넘침 없음을 브라우저에서 확인했다. 커밋·push·운영 배포는 하지 않았다.

## Re;De 브랜드와 폐쇄형 로그인

- 기본 솔루션 이름을 `Re;De`로 변경하고 괄호·세미콜론 형태의 단순 SVG 심볼을 적용했다. 사이드바는 `Re;De` 아래 작은 `Remote Desktop` 문구와 약 66px 높이의 브랜드 영역으로 정리했다. 관리자가 설정한 별도 제목은 기존처럼 우선하며 로컬 모의 서버 제목만 새 이름으로 맞췄다.
- 로그인 화면은 심볼과 이름을 가로로 배치하고 아래에 작은 `Remote Desktop` 문구를 표시한다. 중복된 로그인 설명은 제거했다. 라이트·다크 로고 SVG, 180px 터치 아이콘, 256px PNG와 16/32/64/256px ICO는 `scripts/build-brand-icons.ps1`로 생성하며 운영 제공 파일은 교체하지 않는다.
- 사용자 이름은 `type="text"`, 비밀번호는 `type="password"`와 고정 ID·name을 사용한다. `autocomplete="username"`·`current-password`, 연결된 label과 실제 form의 submit 버튼으로 브라우저 자동완성·암호 관리자 인식 기준을 맞췄다. Enter는 폼 제출 흐름을 사용하고 요청 중 중복 제출을 차단한다. 실제 암호 관리 확장 프로그램의 저장·자동 입력 인수는 하지 않았다.
- 테마 초기화를 로그인 이전 공통 단계로 옮겼다. 저장된 테마 선택이 없는 첫 방문은 다크이며 기존 사용자 테마 선택과 전환 기능을 유지한다. 별도 로컬 주소의 첫 방문에서도 다크 배경을 확인했다.
- 상위 API의 `app.public-account-actions` 기본값은 `false`다. 직접 가입·이메일 비밀번호 복구 API는 허용 플래그가 없으면 기존 오류 응답 형식의 `code: 101`로 거부한다. 로그인 옵션은 공개 계정 작업 허용 여부를 전달하고, 웹은 버튼과 직접 URL 접근을 함께 막는다. 관리자 계정 발급 및 로그인 후 비밀번호 변경은 유지한다. 운영 환경변수·설정과 사용자 DB는 변경하지 않았다.
- 검증: 프런트엔드 빌드 통과(10.54초), diff 검사 통과. 가입·복구 차단 HTTP 테스트 6개와 WSL Go 1.26.5·CGO 환경의 전체 `go test ./... -count=1` 통과. Windows 기본 Go 환경은 SQLite CGO 미지원으로 전체 테스트를 완료할 수 없어 기존 WSL 환경에서 검증했다.
- 브라우저에서 3개 공개 계정 경로의 로그인 복귀, 로그인 입력 속성·label·form 연결, 키보드 초점, 가로 브랜드, 390px 모바일·768px 태블릿의 가로 넘침 없음을 확인했다. 브랜드 변경은 펼친·접힌 사이드바와 라이트·다크에서도 확인했다. 실제 계정 발급·암호 복구·로그인 제출은 실행하지 않았다.
- 로컬 소스와 미리보기 `dist/`만 반영했다. 커밋·push·운영 배포·운영 웹 리소스 복사는 하지 않았다.
